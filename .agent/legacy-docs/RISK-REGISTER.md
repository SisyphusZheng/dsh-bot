## 0. 风险等级与门禁规则

- **P0（阻断）**：无法发布/无法继续阶段；必须消除或降级到可接受并有用户书面确认。
- **P1（高）**：影响核心体验/安全/成本；阶段门禁前必须有缓解与测试。
- **P2（中）**：可延后但有计划。
- **P3（低）**：记录/观察。

**规则**：任何 P0/P1 风险在对应阶段退出前必须有：触发条件、缓解、验证测试、负责人；未缓解的 P0 不得进入下一阶段；安全/数据丢失类风险不得以「用户已同意」替代技术控制。

## 2. P0 风险展开（必须在对应门禁前关闭）

### R01 单权威失效
- **为什么是 P0**：产品承诺与安全边界都建立在此；失效则 M1 不能 Go。
- **验证**：T11–T14 对抗测试；工具审计；语音进程无执行；双播计数。
- **关闭标准**：所有对抗测试 0 越权；工具全部出现在 DSH 日志；代码级 guard 存在（不只是 prompt）。

### R05 语音路线失败
- **触发**：C 路线 T11–T14 失败或体验不可接受；A 需重写 TTS/音频；D 超预算。
- **动作**：暂停 M2；重评；可缩产品为「文本 Agent + 语音播报」（需用户同意，产品承诺变化）。

### R06 TCC 归因
- **验证**：Nisse.app/子进程分别申请麦克风、辅助功能、屏幕录制；记录系统设置归属；拒绝/撤销后行为。
- **关闭标准**：一次授权可覆盖产品所需权限，或明确可行的 helper 方案；否则缩 CUA 范围。

### R07/R08/R09/R10 安全边界
- **关闭标准**：`review/evidence-security.md` 的 C-01/H-01/H-02/H-03/H-04/M-02 对应测试通过（本表/Traceability 中的 SEC-01/04/05/06/07/08/09/10/11）；无 P0 未缓解；安全评审签署。
- **注意**：不能以「用户已同意」替代；不能以「有审批按钮」替代路径/权限/取消控制。

### R14/R16 发行底座
- **关闭标准**：干净环境构建 + 签名/公证 + 升级失败回滚 + 卸载演练全部有记录。
