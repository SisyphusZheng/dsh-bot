> 状态：2026-10-21（M0 产物）；取代旧 M0–M6 计划。

## 1. M0 — 架构纠偏与事实冻结（当前）

**目的**：停止按错误架构继续投入；建立事实/裁决/风险/门禁。
**不做**：不改产品代码；不做 fork/build；不做语音实验。

**前置**：项目包可读；本机可读 Qwen 源码/DSH 安装包/真机证据。

**工作包（已完成/本轮）**：

1. 资产/差距矩阵（`M0-FACT-BASE.md` §4）；
2. 旧文档矛盾表（§3）与旧稿归档（`assistant/archive/`、`research/archive/`）；
3. 架构裁决与 ADR-0001…0010；
4. 产品定义 v3.1、平台架构 v3.1、执行计划 v2.0、fork 决策 v1.1、seams/gaps 重分类；
5. Spike 规格、ROADMAP、风险登记册、追溯矩阵；
6. README-FOR-REVIEW / PROMPT-TO-REVIEWER 更新；
7. 文档一致性扫描（五引擎/双 Agent/假冻结/旧估算残留）。

**产物**：上述文档 + `review/evidence-*.md`（证据）+ `M0-CHANGES.diff`（变更记录）。

**测试/验证**：文档 grep 扫描；交叉引用检查；证据等级抽查；用户/评审人确认。

**退出标准**（必须全部满足）：

- 全仓（历史档案除外）不再出现「五个同级可替换引擎」「AgentEngine 可替换 DSH」「QwenAudio 是第二 Agent（作为目标）」「不修改 DSH 核心（绝对）」「M0 已冻结」「七门禁全 PASS」；
- 资产矩阵、风险登记、追溯矩阵、Spike 规格、ROADMAP 互相引用且无冲突；
- 所有高风险未知项有实验计划/负责人/门禁；
- 产品目标明确包含普通桌面用户与 macOS/Windows/Linux 分阶段；
- 用户批准进入 M1（明确回答 `M0-FACT-BASE.md` §7 的 D1–D6）。

**风险/回退**：若证据不足，M0 可延长但不跳过；不允许「先写代码再补裁决」。

**估算**：3–5 工程人日；日历约 1 周；置信度高。

**结束后用户得到**：一份可执行的架构/路线/风险包，不再被旧文档误导；可决定是否投入 M1。

## 2. M1 — DSH × Voice + Bot 编排 + Hindsight 记忆（三个最小 Spike）

> **v3 修订（2026-10-21）**：Route A 冻结（Bot 顶层逻辑编排、不修改 DSH 核心）；Hindsight 固定为唯一长期记忆后端；
> 任务书见 `M1-WORK-PACKAGES.md`；阶段提示词见 `M1-SPIKE-PROMPTS.md`；需求见 `M3-REQUIREMENTS-BOT-MEMORY.md`。
> 旧 W0–W5 拆解并入 M1-A（证据 `spike/dsh-voice/evidence/`）。

**目的**：在保留实时语音体验的前提下证明 DSH 是唯一 Agent；并证明 Bot 逻辑编排与 Hindsight 记忆可集成（均不改 DSH 核心）。

**不做**：不做 fork/build、安装器、完整 UI、多平台；不做第二 Agent；不自研完整记忆引擎；不把 Mem0 对照作为任务。

### M1-A：DSH × Voice Spike（大部分完成）
- 语音→DSH→工具/审批→语音/气泡；T1–T10 + T11–T14 + S1–S7；路线 C/A/B/D 比较；
- 隔离 `DSH_HOME`；崩溃/取消/重复/迟到；指标与 TCC；
- 剩余：T5（播报中打断 ≤500ms、停播报≠取消任务）、T7（审批绑定/并发/迟到/语音误批）、A/C 听感；
- Go 判据：SPIKE §8（T1–T10 全过、T11–T14、S1–S5）；当前 **Conditional**。

### M1-B：Bot Session Orchestration Spike（未开始）
- 先审计 DSH API 能力（`DSH-API-CAPABILITY-MATRIX.md`）；不修改 DSH 核心、不建 session 父子树；
- 实现：会话索引/搜索/创建/重命名/归档；L1/L2 路由（不静默劫持）；摘要（来源/时效/token 预算）；
  接管/单写者锁/冲突/恢复；Bot/session/subagent 预算；跨层审批/取消/审计；fail-closed；
- 契约：`BOT-SESSION-ORCHESTRATION.md`；验收见任务书 §3 B7；需证明“未修改 DSH 核心”。

### M1-C：Hindsight Memory Spike（未开始）
- 先核实 Hindsight 固定版本/许可/本地运行/SDK/依赖/资源/外发/打包；
- 实现薄 `MemoryAdapter`：search/write/forget/export、命名空间、单写者、敏感拦截、错误映射；
- 行为：显式写入/自动抽取开关、去重/冲突/时效、删除不可召回、导出/迁移、备份恢复；
- 基准：10k（100k 前）检索/写入/存储/token 预算；隐私/外发清单；
- 规格：`MEMORY-SERVICE-SPEC.md`；No-Go 时提交证据与补救，等用户裁决，不擅自换后端。

**前置**：M0 通过；真实模型 Key + DashScope Key；隔离 `DSH_HOME`；Hindsight 获取/联网许可（M1-C）；M1-A 已有 harness/证据。
**退出**：A/B/C 三份 Spike 均通过 + 单权威/安全/隔离证据；任一 No-Go → 停止并回报，不得带病进 M2。
**估算**：M1-A 剩余 2–4 人日；M1-B 6–10 人日；M1-C 6–10 人日（含 Hindsight 核验/基准）；置信度中低，以 Spike 结果修正。

## 3. M2 — DSH 发行底座与可复现构建

**准备状态**：[M2-PLAN.md](M2-PLAN.md)（计划、就绪度、模板与预检；正式开工需 M1 正式 Go + 用户提供上游仓库/网络许可）。

**目的**：证明 Nisse 不依赖作者机器/手工 patch；fork/build/upstream 可维护。
**不做**：不做产品 UI、不做安装器（只做构建与隔离底座）。
**v3 新增**：Hindsight 固定版本/本地运行时/依赖/许可需纳入构建与安装验证；Host Integration 契约测试；Route A“无核心修改”检查。

**前置**：M1 Go；**DSH 上游仓库可获取**（clone 权限或源码树）；构建环境（Node 24/pnpm/Electron/原生依赖/网络）。

**工作包**：

1. 建立 fork/remote/分支/tag 规则；`UPSTREAM.txt`；`nisse/patches/` manifest 规范；
2. 在干净环境构建上游基线（记录依赖、命令、耗时、失败）；
3. 加入最小 Nisse 产品目录/发行 profile（Host Integration 占位即可）；
4. patch queue 初版（如果 M1 证明需要 core patch）；每个 patch 有测试/owner/删除条件；
5. 至少 2 个上游 release 的 merge/rebase 演练（记录冲突/耗时/失败测试/新增 delta）；
6. 独立 `DSH_HOME`/profile 启动测试；确认不写用户 `~/.dsh`；
7. 生成依赖/许可/SBOM 清单；确认 DSH 无根 NOTICE 的补位；品牌/账号/遥测裁剪结论；
8. 建立 CI（至少构建 + 契约烟雾 + patch apply check）。

**产物**：可复现构建文档；`UPSTREAM.txt`；patch manifest；merge 演练记录；隔离启动测试；license/SBOM；CI 配置；`m2-report.md`。

**测试**：干净环境构建；patch apply/rebuild；merge 后 DSH 测试 + Nisse 烟雾；隔离 HOME 写入检测。

**退出标准**：

- 干净环境按文档可构建且产物可运行；
- 至少一次真实 merge 有冲突/耗时记录（不是「无冲突」的假设）；
- 每个 patch 有 owner/理由/测试/删除条件；
- 独立 DSH_HOME 可启动，用户 `~/.dsh` 零写入；
- 许可/SBOM 可生成；
- 若 merge 成本超阈值（ADR-0005），触发降级/重评，不硬扛。

**失败/回退**：上游不可得/构建不可复现 → 改 pinned npm runtime（R2-N 降级），放弃源码 patch；M1 的集成层设计需相应调整（可能需私有协议或 core patch 例外）。

**估算**：8–16 工程人日（基准 12，保守 24）；日历 3–5 周；置信度低（构建/上游未知）。
**并行**：CI/许可清单可与 merge 演练并行；**串行**：构建 → patch → merge。

**结束后用户得到**：可在干净环境复现的 Nisse 构建底座 + 上游同步成本数据。

## 4. M3 — 一体化 Runtime、Shell 与 Product Contract

**目的**：让 Nisse 成为真正独立的产品运行时：一个 App 启动/监督 DSH + Voice，完成语音任务，不依赖用户 DSH。
**不做**：不做完整 MVP UI/记忆/安全闭环（M4）；不做签名/更新（M6）。

**前置**：M2 Go；M1 集成层代码/结论；macOS TCC 实验计划。
**设计输入**：[M3-M4-DESIGN-INPUTS.md](M3-M4-DESIGN-INPUTS.md)（性能/语音架构/安全）；**v3 新增**：Bot 顶层逻辑编排（`BOT-SESSION-ORCHESTRATION.md`）、Hindsight memory runtime（`MEMORY-SERVICE-SPEC.md`）、不修改 DSH 核心。

**工作包（顺序）**：

1. Supervisor：启动/停止顺序、健康检查、单实例、退出清理、崩溃重启、孤儿回收；
2. DSH host 子进程：独立 `DSH_HOME`、发行 profile、Host Integration 打包、版本握手；
3. Voice Runtime 子进程：替换/剥离 Qwen 壳内嵌 gateway，设备所有权、IPC、心跳、崩溃处理；
4. Product Contract v0：ID/状态/命令/事件/错误（ADR-0008）；契约测试；
5. 产品层最小状态机：idle/listening/thinking/working/waiting-approval/speaking/error；UI 接入；
6. 故障注入：杀 DSH/Voice/renderer、断网、设备丢失、版本不匹配；
7. TCC/权限：麦克风、辅助功能、屏幕录制（如启用 CUA）归因实测；引导文案；
8. `~/.dsh` 零污染测试；数据目录/日志/凭据隔离。

**产物**：可启动的 Nisse 开发版（非安装包）；Supervisor/Contract/集成层代码；故障注入脚本；TCC 记录；`m3-report.md`。

**测试**：启动/退出/崩溃矩阵；契约测试（ID/顺序/终态一致）；无孤儿端口/进程/锁；`~/.dsh` hash 对比；一次真实语音任务（不打开 DSH UI）。

**退出标准**：

- 启动 Nisse 后可完成真实语音任务，不需要另开 DSH UI/装插件；
- 任一子进程故障 UI 显示正确状态且可恢复；无孤儿；
- 取消/审批/终态跨进程一致；
- `~/.dsh` 零写入；
- 版本不匹配 fail-loud。

**失败/回退**：DSH host 无法稳定嵌入 → 评估 core patch/私有 API；仍失败 → 暂停产品化，回到 M1/M2 重评。

**估算**：15–22 工程人日（基准 18）；日历 4–6 周；置信度中。
**并行**：UI 状态机与契约测试可并行；**串行**：Supervisor → DSH/Voice 集成 → 故障注入。

**结束后用户得到**：一个可日常启动、说话办事、故障可见的 Nisse 开发版（仍非可分发包）。

## 5. M4 — MVP：主路径、人格、记忆、安全闭环

**目的**：少量但真实可用的端到端场景 + 安全/记忆闭环。
**不做**：不做漂亮首启/多平台/订阅/OE/高级主动性。

**前置**：M3 Go；记忆 schema 设计；威胁模型/安全测试计划。
**设计输入**：[M3-M4-DESIGN-INPUTS.md](M3-M4-DESIGN-INPUTS.md)（P1–P9 性能、S1–S7 安全）；**v3 新增**：Hindsight MVP 记忆（迁移/编辑/删除/导出/预算）、Bot 会话管理 UX。

**工作包**：

1. 主路径 1：语音问答/搜索 → DSH 回答 → 语音+气泡；
2. 主路径 2：低风险文件任务（可逆）→ 审批（如需）→ 执行 → 汇报；
3. 主路径 3：任务进度/「刚才做了什么」；
4. 主路径 4：打断/停止/取消/急停三分语义与 UI；
5. 人格：单一来源（preset/persona）、编辑、下一轮生效；
6. 记忆 v1：schema（profile/facts/worklog/projects/notes）、tools、prompt section、迁移、查改删导出、删除后不召回；
7. 安全：审批绑定/过期/撤销、always-allow 作用域+审计、路径校验（realpath/symlink/..）、取消后无新动作、日志脱敏、L3 默认拒绝；
8. 审计：审批/取消/急停/记忆变更本地记录；
9. E2E 测试套件 + 安全测试矩阵（见 TRACEABILITY）+ 7 天 dogfood。

**产物**：MVP 代码/测试；记忆迁移工具；安全测试报告；dogfood 记录；`m4-report.md`。

**测试**：主路径 E2E；并发/迟到/重复；审批串轮；取消竞态；路径负例；记忆 CRUD/迁移/删除/导出；密钥不入记忆/日志；崩溃恢复。

**退出标准**：

- 主路径 8 项全部可复现；
- 安全测试矩阵 P0 全过；严重未缓解风险 = 0；
- 无双重回答/错误审批归属/取消后新动作等阻塞缺陷；
- 记忆查看/修改/删除/导出/迁移有可复现测试；删除后确实不再召回；
- 作者连续 7 天用真实任务 dogfood，至少 20 次成功语音任务 / 无 P0 事故。

**失败/回退**：若主路径任一不可靠，缩范围（例如先只做问答+只读文件），不硬上 L2/L3。

**估算**：22–32 工程人日（基准 26）；日历 6–9 周；置信度中低。
**并行**：记忆与安全可并行（不同人/不同模块）；**串行**：主路径 → 安全测试 → dogfood。

**结束后用户得到**：一个内部可用、可日常 dogfood 的 MVP（macOS，BYOK，无安装器/签名）。

## 6. M5 — Alpha：产品体验与可用性

**目的**：从「开发者能跑」到「新用户能理解并使用」。
**不做**：不做发行工程（M6）；不做多平台。

**工作包**：首启向导（称呼/人格/Key/语音/权限）；设置页（语音设备/音色/唤醒词/记忆/日志/退出）；状态动画/气泡/任务历史/失败说明；夜间/静音/隐私指示；音频设备切换/重连；网络/Key/额度/权限错误引导；性能测量（冷启动/首响/内存/CPU）；基础无障碍与中英文案。

**产物**：Alpha 构建；用户测试记录；性能基线；`m5-report.md`。

**退出标准**：5–10 名目标用户不看文档完成首启并完成首个语音任务；用户能判断当前状态；无静默失败；关键场景用户测试通过（≥80% 完成任务，主观理解度达标）。

**估算**：15–22 工程人日（基准 18）；日历 4–6 周；置信度中。
**结束后用户得到**：可给外部试用的 Alpha（仍未签名/未自动更新）。

## 7. M6 — 安装、更新、恢复与安全发布门禁

**目的**：从「开发者机器」到「可安装、可升级、可卸载、可恢复」。
**前置**：M5；Apple Developer 账号/证书；CI/发布环境；更新 feed。

**工作包**：签名/公证/硬化运行时；安装器（写数据目录/profile/首启）；自动更新 + 回滚；卸载（记忆保留/删除选择）；版本兼容矩阵；升级前备份/迁移/失败恢复；启动循环防护；依赖锁定/SBOM/第三方声明；遥测/隐私开关；安全测试（权限/备份/恢复/更新完整性）；支持文档/已知限制。

**产物**：签名/公证的 DMG；更新 feed/回滚演练记录；卸载脚本；SBOM/许可；`m6-report.md`。

**退出标准**：干净 Mac 从安装包安装并完成首个任务；升级失败可回滚到可启动状态；卸载行为明确且不误删记忆；签名/公证/SBOM 通过；无未解决严重安全/数据丢失问题。

**外部等待**：证书申请/公证 1–4 周（不可控，单列）。
**估算**：12–20 工程人日 + 等待；日历 5–8 周；置信度低。
**结束后用户得到**：可对外分发/试点的签名安装包。

## 8. M7 — Beta / RC / 1.0

**目的**：验证真实使用下的可靠性、可维护性、用户理解度。
**工作包**：连续运行/长任务；故障注入（网络/模型/语音/DSH/磁盘/权限/睡眠/多显示器）；文件操作可逆性/审批/取消竞态；记忆纠错/导出/删除/升级迁移；资源/冷启动/首响/打断指标；试点反馈/任务成功率/接管率；发布回滚演练；上游同步演练；范围冻结/风险审查。

**退出标准（量化初始目标，基线后冻结）**：

- 关键旅程（首启→首任务、语音问答、文件任务+审批、取消/急停、记忆 CRUD）成功率 ≥ 事先定义阈值（建议首轮 ≥80%，1.0 ≥95% 视场景）；
- 无严重安全/隐私/数据丢失缺陷；错误审批/错误归属测试 = 0；
- 主要故障可诊断/可恢复；崩溃恢复时间达标；
- 发布/升级/回滚/支持流程有实际演练记录；
- RC 功能冻结，后续变更走风险审查。

**估算**：20–30 工程人日（基准 25）；日历 6–9 周；置信度中低。
**结束后用户得到**：1.0 发布候选/正式版（macOS）。

## 9. M8 — Windows / Linux

**前置**：macOS 1.0；资源；平台需求证据。
**工作包（Windows 先）**：输入控制/辅助功能/屏幕捕获 spike；窗口/托盘/热键/通知/自启动；音频设备/唤醒/本地依赖；安装器/签名/分发/更新/卸载；路径/权限/数据迁移；架构/硬件矩阵；测试矩阵/支持声明。Linux 仅评估。
**退出标准**：平台 spike 通过；独立测试矩阵；支持声明；成本区间明确。不得用 Electron 跨平台替代平台能力验证。
**估算**：Windows 25–45 工程人日；Linux 20–35（若做）；日历 6–12 周；置信度低。

## 10. M9 — 客户端扩展与长期演进（OE Go/No-Go）

**前置**：M4+，Product Contract 稳定。
**工作包**：OE 一页 spike（设置或任务历史）；兼容性/构建链/性能/维护成本对比；Go/No-Go；回退方案；长期项（主动提醒/项目记忆/更多语音后端/跨设备）各自立项。
**退出标准**：OE 一页可运行并消费契约；与现有 UI 成本对比报告；Go/No-Go 明确；不阻塞核心。
**估算**：3–5 工程人日；日历 1–2 周；置信度中。

## 12. 首个 1–2 周执行任务（M1，批准后立即执行）

**第 1 周**

1. 建立隔离 spike 目录/分支与 `M1-RUN-LOG.jsonl` 事件 schema；确认不写 `~/.dsh`、不安装到 `/Applications`。
2. 启动 DSH host（隔离 HOME/profile）→ 确认 ready/版本/健康；记录启动耗时。
3. 建立最小 Host Integration/夹具：提交一条文本 turn → 收 token 流/终态 → 记录事件。
4. 接 Qwen voice：真实麦克风说一句 → transcript → 提交 DSH → 播报；记录首响/时延。
5. TCC 探针：Nisse 壳/子进程申请麦克风/辅助功能/屏幕录制归因；记录。

**第 2 周**

6. 路线 C：移除/禁用前端执行类工具与记忆/任务；加代码守卫；跑对抗性 prompt 测试。
7. 跑 10 项测试中的 1–5（单 turn、工具、审批、打断、停止播报≠取消）。
8. 路线 A 最小改造评估（Qwen 音频 I/O + 确定性 TTS）与路线 B 降级测量。
9. 记录指标（首响/打断/CPU/内存/包体积）；更新 `M1-RUN-LOG`。
10. 周末输出 M1 中期报告：是否有阻塞、是否继续 C、是否需切 A/D。

**第 2 周末门禁**：若 C 无法通过「对抗性自答/执行=0」，立即停止 C 的大规模改造，转 A/D 评估；不得带病进入 M2。
