# dsh-bot — 技术门禁与产品 MVP 门禁（2026-10-24 修订）

本文件把「语音运行时交付」与「完整个人 AI 助手产品能力」分开跟踪。Gate 2 只负责安装包内语音运行时的可靠交付；产品 MVP 还有独立门禁，不能用 Gate 2 的通过替代。

## A. 技术门禁（保持现有范围）

### Gate 2 — 安装包内语音运行时
状态：**IN PROGRESS**，未 PASS。

关闭条件（4 项，全部满足）：
1. 最终应用身份正确，安装包不依赖开发目录；
2. 目标 Pipecat Worker、独立运行时与依赖随产品交付；
3. 产品包真实 TCC 授权/拒绝/重新授权恢复通过；
4. 安装后真实语音交互、命令式打断、退出回收通过。

当前已验证：包内 NissePet、独立 Electron、开发目录隐藏启动、Bridge `/events`、单实例、退出无残留。  
当前阻塞：PyInstaller Worker 已构建并健康，但正在接入产品包/真实 DSH bridge 与 TCC。

### 已冻结/不重开
- G2：PASS，冻结；
- G3 P0：关闭；
- G3 P1：PASS WITH CONDITIONS；命令式打断契约冻结；
- DashScope 300s：接受延期、根因未确认，不宣称修复；
- 自由插话：未验收，不属于当前契约。

## B. 产品 MVP 门禁（独立于 Gate 2）

### P-M1 长期记忆（Hindsight 产品化）
状态：**NOT DELIVERED**（现有原型/工作区只算基础）。
必须交付：
- Hindsight 本地服务纳入统一运行时与安装包；
- DSH ↔ Memory Adapter 稳定契约；DSH 仍是唯一 Agent；
- 跨会话写入、检索、更新/冲突处理、删除、导出；
- 查看/纠正/删除/导出界面；
- 隐私边界：密钥/认证信息不入记忆；敏感数据不出本地；
- 迁移、备份、恢复；删除后不可再检索；
- 真实跨会话验收，不以当前会话日志替代。

### P-M2 人格与陪伴
状态：**PARTIAL**。
必须验证：称呼、语气、口癖、身份背景、边界和提示词确实影响 DSH 行为，而非只改桌宠外观。

### P-M3 审批、信任与安全
状态：**PARTIAL**。
必须 E2E：危险操作审批、权限范围、用户拒绝、取消任务、急停、审计、敏感屏幕保护、键鼠活动暂停规则。

### P-M4 真实电脑任务
状态：**PARTIAL**。
必须验证：语音 → DSH 工具调用 → 电脑操作 → 危险请求审批 → 完成后语音汇报；不能只证明 DSH 收到文字。

### P-M5 单一对话与任务生命周期
状态：**PARTIAL**。
必须验证：语音与文字共享 DSH 会话；开始/执行/审批/完成/失败/取消状态一致；无第二 Agent、无重复执行、取消后无新增动作。

### P-M6 产品体验与引导
状态：**PARTIAL**。
必须验证：桌宠交互、通知、唤醒/取消、onboarding、统一设置（模型/语音/人格/记忆/权限/凭据）在dsh-bot 内完成，不要求用户管理多目录/多应用。

### P-M7 安装、更新与长期可靠性
状态：**IN PROGRESS**。
必须验证：干净环境安装、升级/回滚、崩溃恢复、卸载、数据备份、签名/公证、隐私说明、长会话稳定性。

## C. 验收原则
- Gate 2 通过 ≠ 产品 MVP 完成；
- 记忆、人格、审批、任务闭环、统一体验各自需要独立证据；
- 不把开发环境证据当作安装包证据；
- 不把命令式打断写成自由插话；
- 不把未复现的 300s 超时写成已修复。
