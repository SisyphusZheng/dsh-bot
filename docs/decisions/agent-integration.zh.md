# Agent 接入决定

状态：用户已批准的产品约束，适用于 0.0.1—0.0.4；不是已完成实现的描述。

## DSH 与 DS-Bot

DSH 继续提供唯一 Agent Runtime。DS-Bot 是社区 Bot 插件，接入采用复用、适配和必要的最小补丁；不把整个独立应用塞进现有 Electron，也不另起第二套主助手。

优先复用 Bot 身份、Main Bot、会话及已有能力管理；桌宠、Pipecat、现有配置迁移和个人记忆继续属于 dsh-bot。Bridge 连接明确的 Bot 和 Session，输入、审批、取消与事件都带所属请求身份。上游接口不足时记录补丁来源与升级验证，不重写已有成熟能力。

## 记忆

Hindsight 是个人长期记忆的权威服务。DS-Bot 的人格文件、工作记录、对话与群聊记忆按其语义保留；个人事实的读写通过适配器接入 Hindsight。不得把所有文本无差别同步到多个记忆系统，也不得把群聊私有内容自动注入其他 Bot。

迁移先备份、再转换和验证；保留不能转换的原始数据与恢复入口。Bot 身份、记忆所属人和 Session ID 不作为可随意互换的同一个标识。

## 交互与工具

桌宠是 Main Bot 的可交互入口。审批与问答由 Agent 所属服务裁决，主窗口和气泡同步，UI 不自行伪造执行成功。CUA 是 DSH 的工具能力，不是第二个主 Agent；文件、Shell 和浏览器工具继续按任务选择。

## 未来底座

DSH、Pi SDK、LangChain/LangGraph 均可用于构建后续产品；继续使用 DSH 是当前路线。保留消息提交、事件订阅、取消、审批与记忆适配的清楚接口，不为假设中的迁移新增通用多引擎框架。

实际更换底座需要重新验证会话迁移、工具权限、审批、取消、持久化和 DS-Bot 依赖；原版 DSH 插件交付仍需要 DSH 连接能力。只有真实瓶颈与同任务对比证明收益时，才另行立项迁移。
