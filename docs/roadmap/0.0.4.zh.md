# 0.0.4：完整 App 与 DSH 插件双交付

状态：已批准、未开始；依赖 0.0.3。两种交付共享桌宠、语音和请求/事件适配实现，分别验证启动、权限、数据归属与升级。

## 前后变化

完整 App 继续携带隔离的 DSH 环境，适合直接下载安装；插件模式安装到原版 DSH，管理桌宠伴随程序并连接用户选择的 Main Bot。原版 DSH 的浏览器插件不能直接创建另一个进程的 Electron 窗口，因此需要受管理的原生伴随程序；用户仍可以获得一次安装完成配置的体验，具体安装能力必须实际验证。

## 工作项

| ID | 具体任务 | 验收 |
---|---|---|
| V004-01 | 固定完整 App 与插件模式的支持版本、组件协议和能力发现 | 不兼容版本拒绝连接并说明更新对象，不以“已连接”掩盖缺失能力 |
| V004-02 | 插件安装、下载或发现伴随程序；资源固定版本与哈希 | 在原版 DSH 干净安装复现；断网、损坏包和不可执行架构可恢复；不使用 Actions Artifact |
| V004-03 | 明确启动者、所有者、连接者和退出责任 | 桌宠退出不关掉用户现有 DSH；DSH 退出后伴随程序按策略退出或显示离线；无孤儿进程 |
| V004-04 | 连接指定 DSH、Profile、Main Bot、Session 和记忆端点 | 不静默连到另一个 DSH；切换目标有显式确认与状态；不再额外启动重复主助手 |
| V004-05 | 按组件管理数据与凭据，建立备份、迁移和回滚流程 | 不覆盖原 DSH HOME；个人记忆不因卸载桌宠丢失；用户明确选择后才能迁移或合并 |
| V004-06 | 验证本地发现、随机凭据、Origin、端口与连接更新 | 无鉴权不能控制助手，旧 token/旧描述文件失效，拒绝意外远程暴露 |
| V004-07 | 两种交付运行同一套行为回归，另测各自安装与生命周期 | 语音、任务、审批、CUA、记忆和导航能力一致；原版 DSH 场景用真实安装包验证 |
| V004-08 | 写明安装/更新/卸载入口与可选组件大小 | 用户可辨别当前模式、版本和连接对象；保留恢复入口；无未告知的数据删除 |

本版不拆成大规模 Monorepo，不引入第二套 Agent Runtime。可替换底座只保留适配可能性，实际多引擎实现不属于 0.0.4。
