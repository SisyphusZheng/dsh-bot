# dsh-bot 已批准版本计划

本目录是用户于 2026-10-27 批准的产品任务书，描述待交付目标，不表示这些功能已经实现。代码、测试和对应提交的验收记录决定实际状态。

当前事实入口：提交号、产物 SHA、E/U/R 状态与门禁缺口只维护在 [product/CURRENT-STATUS.md](../../product/CURRENT-STATUS.md)；本目录不复制这些数字。

## 版本与顺序

| 产品版本 | 目标 | 相对前一版的变化 | 任务书 |
|---|---|---|---|
| 0.0.1-beta2（当前开发线） | 现有修复候选 | 已恢复桌宠体验和语音，完成跨平台回归，仍有产品缺口和原生验收边界 | [基线](baseline.json) |
| 0.0.1 | 稳定现有功能 | 语音故障可诊断，设置按需更新，配置范围明确，启动退出与真实使用回归通过 | [稳定化](0.0.1.zh.md) |
| 0.0.2 | DS-Bot 适配与 CUA | 桌宠连接 Main Bot，任务、审批、个人记忆共享，能观察并操作 macOS 应用 | [Agent 接入](0.0.2.zh.md) |
| 0.0.3 | 陪伴体验与本地发声 | 动作协调、气泡顺畅、系统本地 TTS、简化首启 | [桌宠体验](0.0.3.zh.md) |
| 0.0.4 | 双交付 | 保留完整 App，同时提供原版 DSH 插件与桌宠伴随程序 | [交付方式](0.0.4.zh.md) |
| 1.0（远景） | 统一个人助手 | 云端持续执行、多 Bot 协作、耳机＋Pad、统一记忆与双交付成熟；不在本轮开发 | [1.0 远景](1.0.zh.md) |

当前只执行 0.0.1；后续版本可以做必要的接口准备，但不得以提前开发后续功能拖延稳定化。0.1.0 的长期质量目标不属于本次已冻结执行范围。

本轮 Chief 定位、语音控制、审批与原生验收的具体边界见 [Chief 收尾任务书](CHIEF-0.0.1.zh.md)。

## 执行入口

本地执行者先读 [0.0.1 本地执行计划](LOCAL-0.0.1.zh.md)，再按稳定化任务书工作。[接入决定](../decisions/agent-integration.zh.md)规定 DS-Bot、Hindsight 和 DSH 的关系。

产品版本与 Runtime 版本独立。当前开发线产品版本为 `0.0.1-beta2`（以 [当前事实入口](../../product/CURRENT-STATUS.md) 为准），Runtime 保持已锁定 rc.3；只有稳定化验收完成并经用户批准才将产品改为 0.0.1。不得把上游包统一改成产品版本。

## 状态与证据

任务进度使用 NOT-STARTED、IN-PROGRESS、IMPLEMENTED、VERIFIED；验收结果只使用 PASS、FAIL、BLOCKED-ENVIRONMENT、BLOCKED-EXTERNAL、DEFERRED。IMPLEMENTED 不等于 VERIFIED，计划批准不等于功能已交付。

每项任务记录问题、完成后的用户行为、涉及入口、依赖、验收和证据。新结果存入独立的 review 目录并绑定源码与产物身份，历史记录保持原样；用户提供的本机结果标明来源，未落库的原始证据不伪装成仓库内证据。

## 固定约束

- DSH 是 0.0.1—0.0.4 唯一 Agent Runtime；Pipecat 继续负责当前语音链路，Hindsight 继续负责个人长期记忆。
- 保留已恢复功能；清理旧链路前证明无引用、记录替代入口并验证回归，不删除用户数据。
- 全部安装、构建与测试在执行者机器完成。禁止 dispatch、重跑或使用任何 Actions Runner，不把 CI 状态作为验收。
- 推送前检查目标分支、默认分支、未关闭 PR 与 Workflow 事件；保留跳过 CI 标记。无法排除 Actions 风险时交付 bundle，不盲目推送。
- 不自动发布 tag、Release 或宣布正式版。后续合并按用户另行指令执行；当前只推送 work/0.0.1-closure，不更新 main。

GitHub Issues 可引用任务 ID 和本目录，任务范围和验收标准只在仓库维护一份。
