# Chief 桌宠：0.0.1 交互与交付契约

[English](CHIEF-0.0.1.md) | 中文

本任务书定义本轮收尾和后续接入的边界。产品仍为 0.0.1-beta；通过云端自动检查不等于通过 Mac、真实麦克风或真实模型验收。实际记录见 [本轮检查点](../../review/0.0.1-rebuild-2026-10-29/CHECKPOINT.json)。

## 产品身份

桌宠所代表的 Nisse 就是未来 DS-Bot 的 Chief/Main Bot，负责理解目标、调用其他 Bot、协调审批和汇报结果。它正在忙、等待用户或空闲，都是合理状态；不在 Chief 上面再创建一个主助手。

DSH 提供唯一 Agent Runtime，Pipecat 负责媒体、ASR/TTS 适配和语音事件，Hindsight 保存个人长期记忆。当前版本不交付 DS-Bot 团队调度或云端运行，也不改用另一套 Agent Runtime。

## 0.0.1 的交互契约

- 用户能听到欢迎语，看到收音反馈，使用 hold/toggle/always、全局 Option、离线唤醒、人格和皮肤；拖动、双击、问答和记忆均保留。
- 播报、收音和任务分别管理。“停止/别说了/取消”停止播报；“停止任务/取消任务”才向 DSH 发送有身份约束的取消。旧口令仍有响应，不把停止指令提交成新工作。
- Chief 忙时，普通新工作进入当前语音 Worker 的内存队列并提示已排队；明确的允许、拒绝和任务状态控制不排在工作后面。队列不是跨进程持久任务系统，Worker 重启不承诺恢复未提交工作。
- 语音“允许一次/拒绝”只处理唯一、仍有效的审批；模糊、重复、过期或多项请求不能产生授权。持续允许只通过查看实际参数后的二次点击确认。
- 持续授权只匹配同一工具、工作目录和完全相同的参数；可在右键菜单撤销。损坏文件停用且保留原文件，不根据原因文本、路径子串或工具名批量放行。
- 录音取消只丢弃录音；媒体连接断开只撤下该连接，已提交的 Agent 任务继续。退出整个 App 仍走既有 Host/Memory 清理流程，不承诺退出后继续本机执行。
- 任务执行状态不明时停止自动推进，提供只读状态检查。用户先确认结果和副作用，再决定重新发起；不伪造“继续”，也不自动重放可能已执行的工具。

## Mac 本地执行

从已提交且干净的工作分支执行现有 [构建脚本](../../product/tools/build-macos.sh)，对生成的同一 DMG 执行 [原生验收](../../product/tools/accept-macos.sh)。签名检查和 LaunchServices 首启/重启不能用直接执行二进制替代；未公证状态与签名有效性分别记录。

```bash
bash product/tools/build-macos.sh
bash product/tools/accept-macos.sh /absolute/path/to/candidate.dmg
bash product/tools/install-macos.sh /absolute/path/to/dsh-bot.app
```

安装默认使用 ~/Applications/dsh-bot.app；已存在应用时不覆盖，明确传 --replace 才备份后替换。保留用户数据，不关闭 Gatekeeper、不移除 quarantine。TCC、外放欢迎语回采、十轮真人对话、连续抢话、蓝牙耳机和鼠标穿透必须由真实用户验收。
