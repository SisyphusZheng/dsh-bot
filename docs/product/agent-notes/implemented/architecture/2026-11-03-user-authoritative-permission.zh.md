# Agent Note：User-authoritative Bot permission preset

Status: implemented

[English](2026-11-03-user-authoritative-permission.md) | 中文

## 问题

Bot 会话在每次冷启动时都被固定为工作区写入档，而界面上显示的是用户自己选择的“完全权限”。前台显示和实际沙箱不一致，用户明确给了完全权限，普通写入仍然被要求逐次审批。

## 决策

Bot profile 把权限档位委托出去（`permissionPreset: user-default`）。Host 依次解析：会话恢复的用户选择 → DSH 配置的默认档 → 安全档；Bot 设置也可以显式固定某一档。设置页暴露档位（跟随 DSH / 工作区写入 / 完全权限），让可见权限和实际沙箱只有一个来源。默认仍保持工作区写入 + 逐次审批。

## 考虑过的替代方案

- 继续强制安全档、只改界面文案：用户选了完全权限时仍然是谎言。
- 取消安全默认、一律完全访问：默认安装不可接受。
- 只认设置里的值、忽略会话恢复：重启后丢失用户上次在会话里的选择。

## 后果

用户选择完全权限后就是完全权限，冷启动后依然如此，审计日志会记录变化。权限服务缺失或异常时回退到安全档，而不是跑得比请求更宽。
